## 12. 通知の差分判定をレス単位に(既存スレの新着レスを検出)

ユーザー指示: 「最近ずっと "新着なし。投稿をスキップします" になってて判定が何か
おかしい気がする。前回との比較ってやれてるの?」

### 原因(現状の仕様)

- `notify.mjs` の差分は**スレ単位のみ**: 状態ファイルには既知スレ ID の一覧
  (`knownIds`)だけを保存し、「新しく見つかったスレ」があるかしか見ていなかった
- 既存スレに新しいレスが付いてもスレ ID は既知のまま → 一切検出されない
- 特に **メインスレ(directThreads の固定スレ 1 本)は初回実行で「既知」になった
  時点で、以後レスが付いても永遠に新着なし**になる(地域別スレは新規スレの
  立ち上がりでのみ通知されていた)

### 対応(nofify.mjs — レス単位の差分)

- 状態ファイルを `{ knownIds, knownPosts }` に拡張。`knownPosts` は
  **スレごとの既知最終レス番号**(`{ "id-2": 1263300 }` 形式)
- 差分の考え方:
  - 新規スレ(knownIds に無い)→ 取得窓内の全レスが新着(従来どおり)
  - 既存スレ → 既知の最終レス番号より大きいレス番号のレスが新着
- **基準(knownPosts)は単調に進める**: レス窓の関係で 1 回だけレスが取れない
  実行があっても基準が下がらず、同じレスを重複通知しない
- **本文未取得スレ**(詳細 JSON が無いスレ)は基準を進めない → 詳細が取れた
  次回に新着として通知される(取りこぼさない)
- 新規スレでも通知できるレスが 0 件(全レスが窓外)ならエントリを作らない
  (空スレで件数だけ増えるのを防ぐ)
- 旧形式(knownIds のみ)の状態ファイルはそのまま読める
  (knownPosts なし → 初回と同じく既存スレの窓内レスをまとめて新着扱い)
- 通知内容・投稿者ごとグループ化・元スレ見出しは従来どおり。
  gist の description と見出しにレス数を追加
  (`新着投稿 N 件(投稿者 M 名 / スレ K 件)`)
- 実行サマリに `notify.newPosts` を追加 → `log/latest-run.md` の通知行は
  `投稿あり(新着 N スレ / M レス)` 形式

### 検証(ダミー gist API / Discord webhook サーバ + /tmp コピーで実施)

- 既存スレの基準(1263295)より大きいレスのみ新着検出(4 レス)✓
  + 新規スレ 1 件(2 レス)→ `新着: 2 スレ 6 レス` ✓
- 同じデータの再実行 → `新着なし`(重複通知しない)✓
- 既存スレに 1 レス追加 → `新着: 1 スレ 1 レス` でそのレスだけ通知 ✓
- 詳細ファイルが無い実行 → 新着なし & **基準を進めない**(baseline 維持)✓
- 窓が下がる(基準より古いレスだけの実行)→ 重複通知なし & 基準不変 ✓
- レス 0 件の新規スレ(窓外のみ)→ エントリに含めない(件数に乗らない)✓
- `npm run batch` 相当(index → notify → run-log)の一連も OK ✓
- `node --check` OK ✓

### 運用上の注意

- **既存の状態ファイル(knownIds のみ)からの移行時は 1 回だけ新着多めになる**
  (knownPosts が無いので各スレの窓内レスを新着扱いする)。1 回目だけ gist が
  大きくなる可能性がある点に注意
- 通知は 5〜20 分おき実行のたびにレス単位で届くようになる(間隔が空いた分の
  レスも窓内ならまとめて通知される)

## 13. メインスレの本文に付帯情報行が混入する不具合 + 募集削除レスの除外

ユーザー指摘: 「gist投稿をいくつか見ると、地域の付帯情報と IP の行の間に広告文言が
紛れている。スクレイピングミスっぽいものがある」+「最終的に本文が空もしくは
2 文字以下のものは募集削除の可能性が高いので最終的な gist には載せないでほしい」
(※ 実際の gist 出力に含まれていた投稿本文・IP 等の具体的な値はこのログには書かない)

### 原因(本文混入)

- メインスレ(日時行 → レス番号行の順)のチャンクは **本文の後に付帯情報行が続く**
  (`性別 ：…` / `年齢 ：…` / `地域 ：…` / `IP: …` / `機種情報:`)
- 従来の本文切り出しは「本文の後にある日時行の直前まで」が前提で、日時行が
  先頭にある形式では**日時行が見つからず本文がチャンク末尾まで伸びて**、
  付帯情報行ごと本文に入っていた(フィールド側にも同じ値が入るため gist で
  同一行が二重に見えた)

### 対応(parse.mjs — 共有ライブラリなので Worker サイト表示にも効く)

- `bodyEndIdx()` を追加: 日時行が本文より後にある形式は従来どおり日時行の直前。
  日時行が番号行より前にある形式は**`metaPatterns` のいずれかに一致する最初の行で
  本文を打ち切り**(性別・年齢・地域・IP・機種などのメタ行を本文から除く)。
  OP(スレ主)チャンクも同様
- 打ち切りの判定は行単位で metaPatterns 正規表現をテストするだけなので、
  config に新しいメタ項目を足した場合も自動的に本文から除外される

### 対応(notify.mjs — 募集削除レスの除外)

- **本文が空 or 2 文字以下(トリム後)のレスは gist に載せない**
  (`isNotifiableBody()`)。新規スレ・既存スレの新着の両方に適用
- 除外レスも**既知最終レス番号の進行には通常どおり含む**(後に削除が解除されても
  同じレス番号で再通知されない。また取りこぼしになったように見える二重通知もない)

### 検証(ダミー掲示板サーバ + /tmp コピーで実施)

- メインスレ(日時行が先頭)の本文: サンプル本文 2 行のみとなり、性別/年齢/地域/
  IP/機種のメタ行が混入しない ✓(フィールド側は従来どおり各メタ値を抽出)
- 従来形式(番号行が先頭)の回帰: OP ☆(23 行の本文)・通常レスとも
  本文・メタが正しく分離 ✓
- 通知フィルタ: 本文 空 / 1 文字 / 2 文字 / 空白のみ → 除外、3 文字以上 → 通知 ✓
  (新着 1 スレ 2 レスで gist 中身を確認。除外レスのレス番号は基準に反映され、
  再実行で新着なし)✓
- `node --check` OK ✓

## 15. blackList に投稿キーワード(keyword: 本文部分一致)を追加

ユーザー指示: 「blackListにさ、blackListのメールだけじゃなくてそういう投稿を
している人をスキップ対象にする投稿キーワードをいれたい。メールだけ変えて変な投稿
している人をスキップさせたい」。

### 対応(parse.mjs + index.mjs)

- `blackList` の各要素を **文字列(メールアドレス完全一致)かオブジェクト
  (`{ "mail": "...", "keyword": "..." }`)の混合**に対応:
  - `mail` … メールアドレス完全一致(従来の文字列と同じ。大文字小文字・空白無視)
  - `keyword` … **投稿本文への部分一致**(大文字小文字を無視)。メールを持たない
    レスも対象になる(本文さえ合えば該当)
  - 両方指定した場合は **AND 条件**(両方合致したレスだけ該当)
- 判定は従来どおり `parse.mjs` の `isBlacklisted()`(バッチのみ。Worker は
  メールページを取らないので未対応のまま)
- 不具合修正: `index.mjs` の `splitList()` が全要素を `String(v)` で文字列化して
  いたため、gist 由来の blackList からオブジェクトが消えていた
  (`"[object Object]"` 化)。**文字列は trim、オブジェクトはそのまま残す**形に
  修正(キーワード・性別排除は文字列専用のまま、非文字列を除く)

### 設定 gist での書き方(例)

**オブジェクト形式(推奨。mail と keyword を明確に分ける)**:

```json
"blackList": {
  "mailList": ["black@example.com"],
  "keywordList": [
    "広告の文言",                                   // 本文部分一致(文字列でもよい)
    { "keyword": "営業", "mail": "x@example.com" }  // 両方合致したときだけ該当(AND)
  ]
}
```

**配列形式(従来・後方互換)**:

```json
"blackList": [
  "black@example.com",          // メール完全一致(従来どおり)
  { "keyword": "広告文言" },     // 本文部分一致(メールを変えても本文が同じなら該当)
  { "mail": "x@example.com", "keyword": "営業" }  // 両方合致したときだけ該当(AND)
]
```

(オブジェクト形式は `index.mjs` の `normalizeBlackList()` で配列形式に
正規化されてから判定される。どちらの形式でも動作は同じ)

### 検証(ダミー掲示板サーバ + /tmp コピーで実施)

- ユニット: メール完全一致(大文字小文字・前後空白)/ keyword 本文部分一致
  (大文字小文字無視)/ mail + keyword の AND(片方だけでは非該当)/
  空オブジェクト・空 blackList は非該当 ✓
- e2e(gist 設定に文字列 1 件 + keyword 1 件 + AND 1 件):
  **2 件除外**(メール一致 1 件 + keyword 本文一致 1 件)✓。
  初回は splitList の文字列化バグで keyword が効かなかった(上記の修正で解消)
- e2e(オブジェクト形式 `{ mailList, keywordList }`): 同じく 2 件除外
  (mailList のメール一致 + keywordList の本文一致。AND 形式は片方だけでは
  非該当)✓
- 正規化ユニット: 配列形式 / オブジェクト形式 / keywordList の文字列+オブジェクト
  混合 / undefined / 空オブジェクト / カンマ区切り文字列(env)✓
- モック回帰(設定なし MOCK=1): 21 スレで正常完了 ✓
- `node --check` OK ✓
