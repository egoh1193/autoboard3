### Dockerfile に gh を戻す(`55b2ad4`)

- ユーザー指摘「Dockerfile に gh コマンドが入ってない気がするけど消した?」
- 調査の結果: **main の Dockerfile には init コミットから gh は入っていなかった**。
  `gh` + `git config user.name` を含む版は **stash(stash@{0} の WIP コミット)にのみ
  存在**。stash したまま戻ってこなかったもの
- apt 一覧に `gh` を戻した(stash 版の git config 行は別途相談)

### `npm run setup`(コンテナ入室後の認証セットアップ)(`66e0af6` → `15c0ca1`)

- ユーザーの運用: `docker run --rm -it -p 9000:9000 -v "$(pwd):/work" -e GH_TOKEN=...`
  で入ったあとのセットアップを 1 コマンド化
- やること: ①GH_TOKEN で gh 認証 ②`gh auth setup-git` ③git config
  (user.name / user.email)④node_modules 無ければ npm install
- **gh 無しイメージでも動くフォールバック**(複数回の失敗を経て完成):
  - `command -v gh` が無い or `gh auth login` 失敗(例: fine-grained PAT は
    `gh auth login --with-token` で弾かれる)のときは、**git の credential.helper で
    `$GH_TOKEN` を push 時に展開**する方式に自動切替
  - credential.helper の文字列は `.git/config` に `$GH_TOKEN` のまま保存されるため
    **トークンはディスクに書かれない**(実行時に環境変数から展開される。検証済み)
- 検証: ローカルで stub gh + テストリポジトリで両ルート動作確認。
  実運用で push 成功(コンテナ内 credential.helper ルート)
- 運用メモ: トークンを会話に貼ってしまったため**失効・再作成を推奨**。
  fine-grained PAT は対象リポジトリへの Contents: Read/Write 権限が必要
  (push が 403/401 ならここを確認)

### `npm run dev` をコンテナ外からアクセス可能に(`1343e40`)

- ユーザー指摘「npm run dev で起動してもコンテナ外からアクセスできない」
- 原因: wrangler dev のデフォルト待受は **127.0.0.1 のみ** → `-p 9000:9000` の
  ポート転送を経由した外部アクセスに応答しない
- 対応: dev スクリプトに `--ip 0.0.0.0` を追加。
  `Ready on http://0.0.0.0:9000` での起動を確認
