## 2. deploy.yml の失敗修正(wrangler.jsonc × wrangler 3.90.0)

GitHub Actions の `deploy.yml`(`cloudflare/wrangler-action@v3`)が
「`npx` exit code 1 / 🚨 Action failed」で失敗していた。

### 原因

- wrangler-action@v3 が Wrangler **3.90.0** をインストールしていたが、
  このバージョンは **`wrangler.jsonc`(JSONC 設定)に未対応**(対応は 3.91 以降)
- 設定ファイルを読み飛ばした結果 `Missing entry-point` エラー → exit 1
- ローカルは最新(4.129.0)で通っていたため差が露出した。`npx wrangler@3.90.0 deploy --dry-run`
  をローカル実行して同一エラーを再現し確定

### 対応

- `wrangler@4`(4.129.0)を **devDependency に追加**(package-lock で固定)。
  CI の `npm ci` 後はアクションがローカルの wrangler を検出して使用する
- アクションを `wrangler-action@v3` → **`@v4`** に更新(v4 は node24 ランタイムで、
  同時期に出ていた「Node 20 is being deprecated」警告も解消。入力名は v3 と同一)
- 検証: `npx --no-install wrangler deploy --dry-run` が 4.129.0 で成功 ✓

### 追加修正(同日)

- v4 に更新後の再実行で `CLOUDFLARE_API_TOKEN 未設定` エラー(→ exit 1)が発生。
  Cloudflare はまだ使わないため、**シークレット未登録の間はデプロイステップをスキップ**する
  ガードを追加(`if: env.CLOUDFLARE_API_TOKEN != ''` + スキップ時の案内ステップ)。
  登録後は再変更なしで自動デプロイに復帰する

## 4. 実サイト URL の環境変数指定(手元での実モードテスト)

手元で実際のサイトにアクセスできるか試すため、実サイトの URL を
**環境変数 `SCRAPER_TARGET_URL`** で指定できるようにした(リポジトリ・config.json に書かない)。

- `index.mjs` の `loadConfig()`: 既定値 ← config.json ← **環境変数 `SCRAPER_TARGET_URL`** の順にマージ(空文字は無視)。`MOCK=1` の方がモック判定としては優先
- CI(`scrape.yml`)の Scrape ステップにも `SCRAPER_TARGET_URL: ${{ secrets.SCRAPER_TARGET_URL }}` を追加 — シークレット登録だけで実モードに切り替え可能(`SCRAPER_CONFIG` JSON 全体を登録する必要がない)
- 使い方: `SCRAPER_TARGET_URL='https://実サイト/public/board/?id=14' npm run scrape`
- 検証: 環境変数あり → `対象: https://example.com/` と実モードで実行されネットワークアクセス成功(0 スレ → フィルタエラーは想定どおり)✓ / 環境変数なし → 従来どおりモックモード 20 スレ ✓

### 追加: 詳細取得件数の上限(SCRAPER_MAX_THREADS)

実サイトでの手元テストで「超遅い」問題 → 原因は設計どおりの礼儀正しさ
(全リクエスト前の 1500ms 待機)+ フィルタ未指定での**全スレ詳細取得**
(1 スレ = 詳細ページ + メール送信ページの複数リクエスト)。

- 環境変数 `SCRAPER_MAX_THREADS` で詳細取得を先頭 N スレに制限できるようにした
  (**一覧 JSON は制限前の全件を出力**、詳細ファイルは制限対象のみ — 失敗スレを
  resCount 掲載のまま残す既存規約と同じ)。バッチ専用の動作確認用フラグ
- 検証: `MOCK=1 SCRAPER_MAX_THREADS=2` → 一覧 20 件 / 詳細 2 件 ✓
