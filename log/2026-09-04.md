# 構築ログ 2026-09-04

掲示板スクレイピング再表示プロジェクトのこれまでの記録。

## 1. 要件の確定経緯

| 項目 | 決定事項 |
|---|---|
| 対象掲示板 | **自営・取得許可済み**の掲示板(大阪の飲み会系掲示板) |
| ホスティング | Cloudflare **Workers**(静的アセット配信 + 動的 JSON) |
| UI / ログ | すべて日本語 |
| 取得方式 | HTML は静的レンダリング → cheerio でパース |
| 通知 | GitHub Actions の定期バッチで新着スレを **Discord webhook** に投稿(投稿内容は仕様未確定・仮実装) |
| スレ絞り込み | スレタイトルに特定の文字列を含むスレのみ抽出(文字列は未指定) |

**2系統のアーキテクチャ**:

```
系統①(サイト):  閲覧者 → Cloudflare Worker(worker/src/) → 対象掲示板をリアルタイム取得
                   → /data/*.json を動的生成 → site/ の静的フロントで表示(300秒キャッシュ)
系統②(バッチ):  GitHub Actions(毎時 cron "7 * * * *") → scraper/index.mjs
                   → scraper/notify.mjs → 新着スレを Discord に通知
```

## 2. ページ構造(対象掲示板は3種類のページ)

1. **スレ一覧ページ**(`https://hoge.com/public/board/?id=14`、全20ページ)
2. **スレ本文ページ**(`https://hoge.com/public/thread/index?id=NNNNN`、スレッド内ページングあり)
3. **個別ページ = メール送信ページ**(`https://hoge.com/public/mail/?type=comment&id=NNNNN`)
   - 実質 `mailto:` リンクのみのページ。**メールアドレスの抽出だけ**が目的

いずれも `<font>` が閉じられない・class 構造がない旧式モバイル掲示板HTML。

## 3. 実装したもの

### 全体構成

- `scraper/parse.mjs` — **共有スクレイピングライブラリ**(Node バッチと Worker の両方から import。Node 専用機能は禁止)
- `scraper/index.mjs` — 系統②バッチ本体。順次取得・`intervalMs`(1500ms)間隔・指数バックオフリトライ
- `scraper/notify.mjs` — Discord 通知(`buildMessage()` / `buildEmbed()` は**仮実装・要調整**)。webhook 未設定なら状態を更新しない
- `worker/src/worker.ts` + `scrape.ts` — 系統①。`/data/*` のみ動的生成、他は静的アセット。Cache API で 300 秒キャッシュ
- `site/` — ビルド不要のバニラ JS フロント(`index.html` / `thread.html` / `app.js` / `style.css`)
- `.github/workflows/scrape.yml`(毎時、デプロイしない)/ `deploy.yml`(コード変更時のみデプロイ)
- `wrangler.jsonc` — Text ルールでモックHTMLを文字列 import、`run_worker_first: ["/data/*"]`

### 巡回パイプライン(4段階 + 個別ページ)

1. (オプション)`categoryList` で掲示板一覧を列挙 — 未設定なら `targetUrl` を直接スレ一覧として扱う
2. スレ一覧(`threadList.nextPage` + `maxPages` でページング)
3. `filters.titleIncludes / titleExcludes` でタイトル絞り込み
4. スレ本文 → hr-split パーサーでレス配列化
5. (バッチのみ)名前欄リンクの個別ページを取得し `mailto:` からメールアドレスを抽出

### hr-split 本文パーサー(旧式HTML向け、config 駆動)

- `<hr>` でチャンク分割 → `<br>` を改行に変換 → 正規表現でレス番号 / 名前 / 日時 / 本文 / 付帯情報を抽出
- 本物のレスは `requireNumberSpan`(`span[id^='b']`)で判別、スレ主(>>1)本文は `opPattern`(`\d+\s*\[☆\]`)で検出
- 付帯情報は `metaPatterns`(年齢 / 性別 / ﾙｯｸｽ / 「〜希望」区分)。**`[^\S\n]` を使用**(`\s` は改行を跨ぐため OP の年齢欄に「性別：男性」が混入する不具合を修正済み)

### 一覧パーサーの規約

- フィールド指定は `"CSSセレクタ@属性"` 形式(`@text` 既定、`@href` など)。url 空の行(広告行等)は自動除外
- **セレクタのマッチは最初の 1 件のみ**(`.first()`)。実物HTMLは `<font>` 未閉鎖で後続の行が入れ子になるため、連結テキストを取ると後続スレのタイトルまで連結される(これで1スレ目のタイトルが「ビール好き集まれ2居酒屋巡り好き(2)…」となる不具合が発生 → 修正)
- `fieldPatterns` — 行テキストへの正規表現抽出。スレ一覧のレス数 `#542` は `<a>` の外側のテキストノードに直接書かれ、CSS セレクタでは取得できないため新設
- スレッド ID は URL から生成(id 系クエリ優先 → `id-76428` 形式)。最初はハッシュ ID(`read-1c4459f`)だったのを改善

### 個別ページ(メール送信ページ)のメールアドレス抽出

- 設定: `thread.mailPage = { linkPattern, emailPattern }`
- hr-split パーサーが本文チャンクの生 HTML から名前欄リンク URL を抽出し `post.mailUrl` に保存
- **バッチのみ**: `post.mailUrl` のページを順次取得(URL 重複は実行内キャストで 1 回だけ)し、`mailto:` からアドレスを取り出して `post.email` に設定
- 系統①(Worker)では実施しない — 1レス=1リクエストで無料プランのサブリクエスト上限 50 に収まらないため

### モックモード

- `targetUrl` がプレースホルダ(`https://hoge.com` / `https://board.example.net`)ならモックモード
- モックファイル(すべて**実物サンプル**): `sample.html`(掲示板一覧) / `sample-thread-list.html`(スレ一覧・梅田板) / `sample-thread.html`(スレ本文・梅田スレ) / `sample-mail.html`(個別ページ)
- モックでは全スレが同じサンプル本文を共有するため、**本文側のタイトルで一覧タイトルを上書きしない**(index.mjs / scrape.ts 両方に同じ条件)

## 5. 修正した不具合・設計変更の記録

1. `??` と `||` の混在で構文エラー → 括弧で明示
2. index.mjs 初版が破損(到達不能 throw / 存在しないモジュール import) → 全面書き直し
3. **metaPatterns の `\s` が改行を跨ぐ** → OP の `age` に「性別：男性」が混入。`[^\S\n]` に統一
4. スレッド ID がクエリURLで不透明なハッシュに → id 系クエリを優先するよう変更
5. `/thread.html?id=...` が Workers の auto-trailing-slash で 307 → フロントのリンクを `/thread?id=` 形式に変更
6. **未閉鎖 `<font>` による入れ子で一覧タイトルが連結** → `extractFieldValue` を `.first()`(最初のマッチのみ)に修正
7. モックで全スレが同一本文を共有 → タイトル汚染防止の条件を両実装に追加
8. wrangler dev の終了不能 /proc スキャンで自己 kill 事故 → 自プロセス除外を追加(運用メモ)

## 8. セキュリティ規約(変更禁止)

- フロント(`site/app.js`)は取得本文を **`textContent` のみ**で描画。`innerHTML` への変更は禁止(取得元HTMLのスクリプト実行防止)
- 対象サーバーへの負荷対策: バッチは 1500ms 間隔 + リトライ、Worker は 300 秒キャッシュ + サブリクエスト頭打ち

## 9. 追加対応(同日): IP・機種情報・添付画像の抽出

ユーザー指示により、hr-split パーサーの抽出項目を拡張。

- **IP / 機種情報**: `metaPatterns` に `ip`(`IP: xxx`)・`device`(`機種情報: xxx`)を追加。日時行より後にあるため本文への混入なし。metaPatterns は共有ライブラリのみで処理するため、**系統①(Worker)のリアルタイム表示にも含まれる**
- **添付画像**: 新設定 `thread.post.imagePattern`(全件マッチ)→ `post.images` 配列。実物では `<img src=".../assets/img/bbs/<スレID>/thumb_xxx.jpg">` のサムネイル 2 枚(17番・22番)を確認済み
- **フロント表示**: IP・機種情報は他の付帯情報と同じくヘッダーのラベル付きで表示。画像は対象掲示板への直リンク埋め込み(`<img>`)を避けて **URL のテキストリンク**として表示(閲覧者のアクセスが対象サーバーに流れるのを防ぐ。`a.target=_blank` + `rel="noopener noreferrer"`)
- 動作確認: 24番 `ip=192.0.2.2, device=iPhone`、23番 `device=A203SO`、22番 `images=2件` ✓(未記載のレスは空欄)

## 10. 通知スタイル変更: Gist 経由に切り替え

ユーザー指示により、Discord 直接投稿(embed)から「**Gist に詳細を投稿し、Discord にはその URL だけを投稿**」するスタイルに変更。

- `notify.mjs` を全面書き換え: 新着スレの詳細(レス全文・年齢/性別/ﾙｯｸｽ/区分/IP/機種情報/画像URL/メール)を Markdown に組み立て(`buildGistContent()`)→ **秘密 gist**(`public: false`)を作成する GitHub API → `buildDiscordMessage()`(スレタイ一覧 ≤10件 + gist URL)を webhook に投稿
- 環境変数: `GIST_TOKEN`(**gist 権限の PAT が必要**。Actions 既定の `GITHUB_TOKEN` では gist を作成できない)、`GIST_API_URL`(テスト用にダミー API へ差し替え可能)、既存の `DISCORD_WEBHOOK_URL` / `STATE_PATH`
- `DISCORD_WEBHOOK_URL` または `GIST_TOKEN` が未設定 → 投稿スキップ + 状態更新なし(従来どおり)
- `scrape.yml` に `GIST_TOKEN` を追加、README / CLAUDE.md 更新
- **テスト時にハマった点**: テストハーネスで `spawnSync` を使うと親プロセスのイベントループがブロックされ、同じプロセスのダミー HTTP サーバが子プロセス(notify.mjs)の fetch に応答できずデッドロックする。非同期 `spawn` を使うことで解決。**notify.mjs 自体に問題はなかった**
- 動作確認(ダミー gist API + ダミー webhook での結合テスト): 初回実行で gist 1件作成(約5.2万字)・Discord 1件投稿・状態保存 ✓、2回目は「新着なし」で何も送らず状態維持 ✓、秘密 gist であること・Markdown に全抽出項目を含むこと・mailUrl を出力しないこと・Discord に本文を直接送らないこと、全 15 項目 OK ✓
